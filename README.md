# 安卓相册备份工具

**只读手机、只写电脑、绝不自动删除。**

## 这是什么

一个**完全离线**的 Windows 小工具，解决一个很具体的问题：

> 手机相册满了，想清理，但不确定哪些照片电脑上已经有了。

它通过安卓系统自带的调试通道（ADB）把相册拉到电脑上，做**双端哈希校验**确认副本完整，
然后生成一份**清理清单**告诉你：哪些可以放心删、哪些千万别删。

它**不是**网盘客户端，**不是**手机助手，也**不会**在你手机里装任何东西。

### 它绝不做的

| | |
|---|---|
| ✗ 自动删除手机上的任何文件 | **不可协商**。删除永远由你手动完成 |
| ✗ 修改原图字节 | 连 EXIF 都不动，哈希逐字节一致 |
| ✗ 使用 AI 模型 / 云端 API | 完全离线，断网可用 |
| ✗ 上传照片到任何服务器 | 数据只在你自己的电脑和手机之间流动 |
| ✗ 要求管理员权限 | 解压即用 |
| ✗ 在手机上安装任何东西 | 用系统自带的调试通道 |

## 核心特性

- **内容去重** —— SHA-256 内容指纹，同一张照片存了两次只备份一份；支持「秒传」（第二次备份几乎不传数据）
- **双端校验闭环** —— 源端 `adb shell sha256sum` 与落盘后本地全量哈希比对，不一致就拦下来重试，绝不含糊过关
- **按时间归档** —— EXIF 拍摄时间 → 视频容器时间 → 文件名时间串 → 修改时间，逐级回退；读不出来的进 `_时间存疑` / `_未知时间` 独立目录
- **双树 + 硬链接** —— 一棵按时间排给人看，一棵镜像手机目录结构用来对账；两棵树是同一份实体，**不占双倍空间**
- **断点续传** —— 中途拔线、断电、Ctrl+C，下次接着传，不重复劳动
- **四档清理清单** —— CSV（带 BOM，Excel 直接打开）+ TXT + 可选的删除脚本
- **本地网页管理页** —— 看进度、看清单、导出报告；手机扫二维码可只读查看
- **反向下载** —— 把电脑上的照片放回手机（换机迁移 / 误删恢复）
- **两种连接方式** —— USB 直连（最稳）或无线（配对码 / ADB over TCP/IP）

---

## 三条铁律

这三点写在设计文档里，也是代码中不可违反的约束：

1. **先落盘 + `fsync`，再写索引** —— 杜绝「索引说有、文件不存在」
2. **只有校验通过的文件才标记 `verified=1`**，才可能进「可放心删」
3. **绝不删除手机上的任何文件** —— 对手机侧只有读操作，
   唯一例外是用户主动调用的反向下载

## 快速开始

### 普通用户（推荐）

下载 `dist/android-photo-backup_v1.0.0_portable.zip`（免安装版），解压后双击 `安卓相册备份.exe`。

**什么都不用装** —— Python、ADB 全打包在里面了，也不需要管理员权限。

三步上手：

```
手机上打开「USB 调试」 → 数据线插上 → 双击「安卓相册备份.exe」
```

> 完整图文步骤（含红米 / 澎湃 OS 的专门说明）见 **[使用说明.md](使用说明.md)** 第 3 章。

### 开发者

需要 Windows 10 / 11 64 位 + Python 3.10 以上（推荐 3.11 / 3.12 / 3.13）。

```bat
:: 1. 安装依赖（自动建 .venv，走清华镜像）
安装依赖.bat

:: 2. 跑测试
python tests\run_all.py

:: 3. 启动
启动.bat

:: 4. 一键打包成 exe 并生成交付 zip
build.bat
```

`build.bat` 会依次执行：依赖检查 → 跑测试 → 离线自检 → 清理旧产物 → PyInstaller 打包 → 生成两个 zip。

## 备份结果长什么样

假设备份根目录设为 `D:\安卓相册备份`：

```
D:\安卓相册备份\
│
├─ 照片归档\                      ← 【平时看照片就看这里】
│    └─ 2024\2024-03\2024-03-15\
│         ├─ IMG_20240315_142233.jpg
│         └─ IMG_20240315_150011.jpg
│
├─ 手机镜像\                      ← 【和手机结构一致，用来对账】
│    └─ 红米K90_A1B2\
│         ├─ DCIM\Camera\IMG_20240315_142233.jpg
│         └─ Pictures\WeiXin\mmexport1710000000000.jpg
│
└─ .photobak\                     ← 【程序内部数据，别删】
     ├─ index.db                  ← 索引库（记录每个文件的指纹）
     ├─ logs\                     ← 日志
     ├─ reports\                  ← 清理清单（CSV / TXT / 删除脚本）
     ├─ backup\                   ← 索引库滚动备份
     └─ tmp\                      ← 传输临时文件（正常应为空）
```

**为什么有两棵树？** 归档树给人看，镜像树给对账用。两棵树之间用硬链接，
是同一份实体，**不会占双倍空间**。

> 备份盘是 exFAT / FAT32（不支持硬链接）时，程序会自动降级为复制，
> 并明确提示「镜像树已降级为独立副本（占用双倍空间）」。
> 不想要镜像树可以把配置里的 `镜像树链接方式` 改成 `off`。

## 清理清单四档

| 档位 | 含义 | 建议 |
|---|---|---|
| **① 可放心删** | 电脑上已有完整副本，且通过了双端哈希校验 | 先抽查几个，确认后再删 |
| **② 建议保留** | 相机原片，价值较高 | 默认不启用；配置 `保留相机原片=1` 可开启 |
| **③ App 缓存可清** | 缩略图、App 缓存，本来就没有备份价值 | 可以删，能省不少空间 |
| **④ 暂不能删** | 未通过校验 / 索引缺失 / 时间存疑 / 超限被拒 / 在 `.nomedia` 目录 | **一律不要删** |

清单以三种形式产出：

```
.photobak\reports\
  ├─ 可放心删_2024-03-20.csv      ← Excel 打开，含手机路径与电脑路径
  ├─ 可放心删_2024-03-20.txt      ← 手机上对照着删最方便
  ├─ App缓存可清_2024-03-20.csv
  ├─ 暂不能删_2024-03-20.csv
  └─ 删除脚本_2024-03-20_请确认后再运行.bat
```

> **关于删除脚本**：里面是逐条 `adb` 删除命令，运行后会**真的删掉手机文件且无法撤销**。
> 程序**永远不会**自动运行它，必须由你双击并确认。
> 更保守的做法是不用它，直接在手机相册里对照 TXT 清单手动删。

**最稳妥的节奏**：第一次备份 → 只删一小部分 → 过一两周确认没问题 → 再删剩下的。

## 技术架构

```
photobak/
├── common/     基建层：错误码表、日志、路径、网络探测、中文文案、显示宽度对齐
├── core/       领域层：配置、索引库、哈希、EXIF、时间、命名、
│               扫描规则、去重、归档、校验、清理清单、体检、反向下载
├── channels/   通道层：只负责「枚举文件」和「读字节」
│               adb_client → adb_source → usb_adb / wifi_adb
├── app/        编排层：状态、会话、主流程状态机
└── ui/         表现层：终端界面、二维码、进度、托盘、FastAPI 网页服务
```

**设计要点**：通道层只负责枚举与读字节，**所有业务规则都在 `core`**。
这样 USB 与 WiFi 两条通道的行为完全一致，将来加第三条通道也不用改业务代码。

### 校验闭环

```
传输（8 MB 分块，内存恒定，可断点续传）
  → 落盘 + fsync
  → 本地全量 SHA-256
  → 与源端 adb shell sha256sum 的哈希比对（双端校验）
  → 可选写后复读校验（捕获磁盘静默损坏）
  → 一致才原子替换到最终路径并写索引
  → 不一致则删除 .part 并指数退避重试，连续失败则拦截
```

### 索引库

SQLite，10 张表：

| 表 | 用途 |
|---|---|
| `files` | 文件主表，`sha256` 唯一 —— 去重只认全等，编辑版 `_edit` 不会被误判 |
| `instances` | 同一内容的不同来源实例 |
| `storage` | 存储位置（相对路径，整个备份目录可随意搬动） |
| `devices` | 设备登记 |
| `transfer_jobs` | 传输任务与断点 |
| `backup_runs` | 每次备份运行记录 |
| `failures` | 失败明细 |
| `scan_roots` | 扫描范围 |
| `settings` | 配置快照 |
| `unbacked_files` | 未备份文件清单（超限 / `.nomedia` / 缓存），供清理清单兜底 |

### 关键实现细节

- **PyInstaller onedir**（非 onefile）：启动快、杀软误报低、无 `%TEMP%` 残留、内置 adb 路径固定
- **`.nomedia` 两遍扫描**：先 `learn_nomedia` 收集标记，再逐条判定，不产生额外 IO
- **路径安全化**：超长路径三级压缩（先压文件名 → 再压目录名 → 最后才用纯哈希名）、emoji 保留、保留名加 `_` 前缀、`safe_join` 防目录穿越
- **终端对齐**：中文 / emoji 按 2 列宽计算（`disp_width()`），ASCII 边框不会被撑歪
- **二维码用字符块渲染**：不生成图片，纯终端输出
- **`.bat` 全纯 ASCII + CRLF**：cmd.exe 按字节偏移读批处理，多字节汉字跨缓冲区边界会被截断；中文输出一律交给 Python

## 命令行参数

```
--usb                     直接使用 USB 通道
--wifi                    直接使用无线配对码方式
--wifi-tcpip              先用 USB 打开无线，再无线连接
--wifi-connect IP:PORT    直接连接指定的无线设备
--doctor                  只做索引体检与修复
--deep                    体检时对文件做完整哈希校验（慢）
--dry-run                 试运行：只扫描，不传输不落盘
--backup-root PATH        指定备份根目录（覆盖配置文件）
--config PATH             指定配置文件路径
--port N                  本地管理页端口
--no-gui                  不启动本地管理页与托盘图标
--yes, -y                 跳过所有确认（自动化用）
--version                 查看版本
```

示例：

```bat
启动.bat --dry-run
启动.bat --doctor --deep
安卓相册备份.exe --usb --backup-root E:\照片备份
```

## 常见问题

完整 15 条 FAQ 见 **[使用说明.md](使用说明.md)** 第 7 章。几个最常遇到的：

**Q：双击 exe 提示「Windows 已保护你的电脑」？**
SmartScreen 对未签名程序的默认拦截。点「更多信息」→「仍要运行」。
本程序完全离线运行，不联网、不写注册表。

**Q：提示「没有找到手机」/「未检测到设备」？**
按顺序查：① 数据线能不能传数据（最常见原因，换根线试试）
② 手机「USB 调试」开了吗 ③ 插上后通知栏改成「传输文件」了吗
④ 弹「是否允许 USB 调试」必须点允许 ⑤ 电脑上的手机助手类软件（小米助手、豌豆荚等）
会抢占 ADB 通道，**先完全退出**再重试。

**Q：备份了两遍会占双倍空间吗？**
不会。内容指纹去重 + 硬链接，两棵树是同一份实体；第二次备份几乎全是秒传。

**Q：备份完手机相册里少了几张没备份？**
多半是那几张在 `.nomedia` 目录里（App 私有内容）被主动排除了。
它们会出现在「暂不能删」清单里。想强制备份就把 `忽略nomedia` 改成 `1`。

**Q：想确认索引和磁盘是否一致？**

```bat
启动.bat --doctor --deep
```

## 兼容性

| 项目 | 要求 |
|---|---|
| 运行环境 | Windows 10 / 11，64 位 |
| 手机系统 | Android 5.0 以上（无线配对码需 Android 11+） |
| 手机端 | **无需安装任何东西**，用系统自带调试通道 |
| 备份盘 | NTFS 最佳（支持硬链接）；exFAT / FAT32 可用但镜像树降级为复制 |
| 网络 | 不需要；无线模式需要手机与电脑同一局域网 |
| 管理员权限 | 不需要 |

已在 **红米 K90 / 澎湃 OS 4.0 / Android 17** 上实机验证：
扫描 770 个候选 → 规则过滤后 407 个（3.97 GB），传输与校验全部通过。
